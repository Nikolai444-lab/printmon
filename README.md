# 🖨 printmon

**Мониторинг остатка тонера в сетевых принтерах.** Один исполняемый файл под Windows,
без установки, без Python и без «а давайте ещё вот это». Опрашивает принтеры по SNMP,
ведёт историю уровней и показывает понятную веб-страницу с состоянием всего парка.

*Toner-level monitoring for network printers (HP, Kyocera, …). Single Windows binary, SNMP only,
local web dashboard, SQLite history, wear-out forecast.*

## Зачем

Обычный сценарий: тридцать принтеров, у каждого свой веб-интерфейс, и «когда у бухгалтерии
встанет печать» узнаётся по звонку. Printmon собирает весь парк в одну таблицу и отвечает
на три вопроса: **где заканчивается тонер, сколько осталось дней и куда нести новый картридж.**

Один раз нашли, что программа окупается сразу: в первом же прогоне по парку из 33 устройств
нашлось десять аппаратов в зоне «пора заказывать», включая один с нулевым картриджем —
то, что глазами по веб-интерфейсам не видно.

## Возможности

**Опрос парка**
- автоматический поиск принтеров по подсети (несколько подсетей сразу), плюс ручное добавление отдельных адресов;
- только **SNMP (UDP/161)** и только чтение: программа не печатает, не меняет настройки принтеров
  и не обращается к их веб-интерфейсам — значит, не требует паролей и не вызывает предупреждений антивируса;
- один опрос — от одной короткой проверки до полного обхода; HP не любит параллельные сессии,
  поэтому к каждому устройству запросы идут последовательно, а по парку — с ограниченным параллелизмом;
- история уровней в SQLite, прогноз «осталось N дней» по тренду расхода (устойчив к тому,
  что SNMP и веб-интерфейс показывают проценты с расхождением в пару пунктов).

**Веб-страница**
- таблица парка: IP, модель, серийник, кабинет, уровни по каждому расходнику с полосками,
  счётчик страниц, статус устройства и время последнего ответа;
- сортировка по любому столбцу, поиск (в том числе по кабинету), фильтры: «ниже 30 %»,
  «заканчиваются», «цветные», «не отвечают»;
- блок **«Пора заказывать картриджи»** — с номером кабинета, чтобы сразу знать, куда идти;
- светлая и тёмная тема, выбор запоминается;
- кабинеты можно править прямо в таблице (клик по ячейке) или залить таблицей CSV из Excel;
- принтеры добавляются и удаляются из интерфейса — правка json вручную не нужна;
- кнопки «Обновить сейчас» и «Остановить программу».

**Мелочи, которые обычно бесят**
- цветные аппараты показываются честно: четыре картриджа, а не «принтер без данных»;
- устройства, отдающие не проценты, а сырые счётчики (например Kyocera `432/7200`),
  помечаются как `raw`, и проценты считаются делением — видно и то, и другое;
- порядок и группировка: «не наше (тест)», исключения вроде коммутаторов, группы;
- браузер с мордой открывается сам при запуске (и только после того, как порт занят);
- закрытие вкладки программу **не** останавливает — мониторинг не выключается случайно.

## Быстрый старт

1. Положите `printmon-gui.exe` (или `printmon.exe`) в папку, например `C:\printmon\`.
2. Запустите.
3. Готово: рядом появится папка `data` с базой истории, а в браузере сама откроется
   вкладка <http://127.0.0.1:49321>. При первом запуске программа спросит, сканировать ли
   вашу подсеть — она сама определит сетевые адреса этого компьютера и предложит их списком.

Два варианта сборки: `printmon.exe` — с окном логов (удобно при первой настройке),
`printmon-gui.exe` — совсем без окна (для автозагрузки).

## Сборка из исходников

```bash
# обычная сборка под текущую систему
go build -o printmon .

# Windows: с окном логов и без окна
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -ldflags "-s -w" -o dist/printmon.exe .
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -ldflags "-s -w -H=windowsgui" -o dist/printmon-gui.exe .
```

`CGO_ENABLED=0` важен: база (SQLite через `modernc.org/sqlite`) и SNMP — чистый Go,
поэтому кросс-компиляция из Linux собирается без mingw.

## Ключи запуска

| Ключ | Смысл |
|---|---|
| `-config printmon.json` | путь к настройкам |
| `-data data` | каталог с базой истории |
| `-listen 127.0.0.1:49321` | переопределить адрес веб-страницы |
| `-noopen` | не открывать браузер при запуске |
| `-nopoll` | не опрашивать сеть, показать только накопленную историю |
| `-once` | один опрос и вывод результата в JSON |
| `-seed printers.csv` | наполнить историю из выгрузки (для проверки без сети) |

## Настройки (`printmon.json`)

Файл создаётся сам при первом запуске. Основное:

| Поле | Смысл |
|---|---|
| `subnets` | список опрашиваемых подсетей, например `["10.0.1.", "10.0.2."]` |
| `hosts` | отдельные адреса вне подсетей (сюда попадают принтеры, добавленные из интерфейса) |
| `exclude` | адреса, которые опрашивать не надо |
| `community` | SNMP community (обычно `public`) |
| `intervalMinutes` | период опроса (по умолчанию 15 минут) |
| `warnPercent` / `critPercent` | пороги «внимание» и «критично» (25 / 10) |
| `historyDays` | глубина истории для расчёта тренда |
| `listen` | адрес веб-страницы, по умолчанию `127.0.0.1:49321` |
| `openBrowser` | открывать ли браузер при запуске |
| `locations` | кабинеты: `{"10.0.1.22": "305"}` |
| `groups` | группы устройств, например `{"10.0.1.30": "не наше (тест)"}` |
| `telegram` | отправка предупреждений в Telegram (по умолчанию выключена) |

## Как это устроено

```
main.go          запуск, расписание опроса, ключи командной строки
snmp.go          опрос устройств, разбор расходников (Printer MIB)
store.go         история в SQLite + импорт выгрузки CSV
view.go          расчёт тренда, прогноз, алерты
web.go           API и отдача страницы
index.html       вся веб-страница (встроена в бинарник через go:embed)
config.go        настройки и их проверка
configstore.go   живая конфигурация + запись файла
netdetect.go     определение своих подсетей
browser.go       открытие браузера по умолчанию
shutdown.go      аккуратная остановка
```

## Ограничения (честно)

- **USB-принтеры не поддерживаются.** SNMP — сетевой протокол, у USB-принтера нет адреса.
  Варианты: принт-сервер USB→LAN либо отдельный локальный агент на компьютере (в планах).
- Веб-страница доступна только с той машины, где запущена программа (`127.0.0.1`).
- Это приложение, а не служба Windows: автозапуск делается ярлыком в автозагрузке.
- SNMP и веб-интерфейс принтера показывают проценты с расхождением в 2–5 пунктов — поэтому
  пороги берутся с запасом, а главный сигнал — тренд, а не абсолютное значение.

## Планы

- служба Windows (запуск без автозагрузки, остановка через оснастку «Службы»);
- просмотр страницы с других компьютеров (с паролем);
- локальный агент для USB-принтеров.
